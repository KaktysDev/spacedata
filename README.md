# Spacedata

A minimal 3D experiment following one AI prompt across a ground route and a Starcloud-inspired orbital route. Drag the Earth, hold and move the origin pin, choose a provider, and send a question. A camera journey ends in a blurred comparison of electricity cost, cooling water, network round-trip time and facility energy. The same real AI workload powers both modeled scenarios.

## Development

```sh
npm ci
cp .env.example .env.local
# Add GEMINI_API_KEY to .env.local for real Gemini requests.
npm run dev
```

Without a key, the full route preview works without a paid call or fabricated answer. Enter sends; Shift+Enter inserts a newline. Location presets and latitude/longitude inputs provide a keyboard alternative to dragging. The scene respects reduced motion and the comparison remains usable if WebGL is unavailable.

```sh
npm run lint
npm test
npm run build
npm start
```

The production build uses webpack. The globe uses Three.js and locally bundled Natural Earth / world-atlas geography. There are no remote map tiles or font downloads. `public/globe-land.json` contains land dots and country boundaries, generated by `scripts/generate-globe.mjs`.

## Gemini and Vercel

Keep your existing **GEMINI_API_KEY** in Vercel, enabled for the deployment environment you use. `GOOGLE_GENERATIVE_AI_API_KEY` is supported as an alias. Neither is exposed to the browser. Model IDs are fixed in `lib/starcloud/catalog.ts`; arbitrary client-supplied models are rejected. The Gemini adapter uses `gemini-2.5-flash`, a 512-token output cap and disabled thinking. It reads provider token counts (including additional billed tokens in the total), excludes thought parts, and labels missing usage as estimated.

For public production chat, add **UPSTASH_REDIS_REST_URL** and **UPSTASH_REDIS_REST_TOKEN** from one shared Upstash Redis database. Redeploy after changing environment variables. Without Redis, the server still calls a configured model and applies an in-memory limit on that instance. If Redis is configured and unreachable, live requests fail closed.

Optional provider keys: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `XAI_API_KEY`. You do not need these for Gemini. Each unconfigured provider remains available as a clearly labeled route preview. The app makes **one** provider request per submission, not two separately billed answers. Cancellation propagates to the server/provider where supported, but already-started work can still be billed.

`CHAT_DAILY_LIMIT` defaults to 200 paid requests per UTC day across every provider and every user. `APP_ORIGIN` optionally pins the canonical browser origin; otherwise the request URL origin is used, allowing Vercel preview URLs. Provider account budgets and Vercel Firewall are useful additional operational controls.

## What the numbers mean

**Measured:** the actual provider call duration and reported token usage. This is not time to first token, the user's full end-to-end latency, or a live datacenter telemetry feed.

**Modeled:** both infrastructure scenarios use identical token workload and adjustable IT energy (default 1.11 J/token, an illustrative parameter). A 0.5–2× energy sensitivity range is shown. Facility overhead uses PUE 1.04 for orbit (assumed), 1.09 for Google (2025 fleet average), or 1.10 for other ground providers (assumed). On-site ground water intensity spans an assumed 0.2–2 L/kWh; orbital evaporative cooling water is zero under a closed-loop radiator assumption. Electricity cost excludes hardware, networking, launch, capital expenditure and provider margin. API fee estimates are shared, separately labeled standard-rate estimates, not invoices.

The nearest site is selected from a **curated, non-exhaustive public reference catalog**, with approximate city/region coordinates. Google datacenters, AWS Bedrock regions, Azure AI regions and xAI endpoint regions are not equivalent kinds of physical sites. The user's pin does **not** control where direct provider APIs actually run the request. The app does not claim to locate private facilities or show real network traces.

Ground propagation follows an illustrative exchange/landing-city graph with a 1.15× cable-length allowance, 200,000 km/s fiber, and 10 ms overhead. Nearby requests use local ISP and regional peering waypoints. Paths follow the surface. The orbital scenario shares the provider ground entry, then uses fiber to a modeled land gateway, an RF uplink to a conceptual carrier relay at 550 km, an optical crosslink into the compute constellation, four further line-of-sight laser links, and the complete reverse path. The comparison uses those same segment distances, with 12 ms total processing overhead. Optical links are checked for Earth clearance and a 4,000 km maximum range.

The scene shows 8,800 representative spacecraft in four altitude rings at 640, 700, 760 and 820 km. Each ring has 20 planes spaced evenly in right ascension around Earth's axis, then a modest inclination near 8°, plus small fixed scatter in node, phase and altitude. Circular periods follow Kepler's law and inclinations follow the first-order J2 sun-synchronous condition. Altitude spacing and hardware sizes are enlarged for legibility; routing distances stay in physical kilometers. Route distances use physical kilometers. Pixel-based level of detail keeps thousands of spacecraft inexpensive at overview scale and restores the detailed hardware up close. The number of bands, per-band population, individual positions, carrier relay and gateway sites are visualization assumptions, not a deployment specification or live ephemeris. Earth's orientation is held fixed in this short illustration; it is not a long-term orbit propagator. Positions freeze at submission so animated links and reported distances agree. The camera establishes one overview and holds it during the trip; animation time is independent of API time and modeled network latency. Weather, traffic, handovers and capacity are not simulated.

The whitepaper describes RF/optical access and inter-satellite communication. Its closely spaced training modules are not equivalent to this planet-scale relay ring: the latter illustrates traffic between separate facilities, not a single sharded GPU training fabric. Nearby ground can be faster than orbit; the app does not force an orbital speed advantage.

## Verification and security

`npm test` runs deterministic geography, scenario, Gemini contract, other adapter and abuse-control tests with mocked provider responses. It makes no paid calls. See [SECURITY.md](SECURITY.md) for the review, deployment requirements and residual risks. Real provider credentials and production deployment must be verified separately; mocks cannot prove a specific key's permissions, quota or billing status.

The illustrated explanation uses figures extracted from Starcloud’s 2024 whitepaper. Image provenance is recorded in `public/research/CREDITS.md`; provider marks and their MIT license are in `public/providers/`.
