# SpaceVision

A minimal 3D experiment following one AI prompt across a ground route and a modeled Starcloud-2 orbital route. Drag the Earth, hold and move the origin pin, choose a provider, and send a question. The camera follows the route packet, then a scrollable results card shows both replies and a comparison of modeled network time, electricity, cooling water, and facility energy. Where a campus photo is verified, the card selects the photo for the modeled site; other images are labeled as regional or provider references. The orbital photo is Starcloud-1, a demonstration spacecraft, not the Starcloud-2 path. Starcloud imagery is credited in the card.

## Development

```sh
npm ci
cp .env.example .env.local
# Add GEMINI_API_KEY to .env.local for real Gemini requests.
npm run dev
```

Without a key, the full route preview works without a paid call or fabricated answer. Enter sends; Shift+Enter inserts a newline. Location presets and latitude/longitude inputs provide a keyboard alternative to dragging. The scene respects reduced motion and the comparison remains usable if WebGL is unavailable.

```sh
npm run lint
npm test
npm run build
npm start
```

The production build uses webpack. The globe uses Three.js and locally bundled Natural Earth / world-atlas geography. There are no remote map tiles or font downloads. Result-card reference photos load from their credited sources. `public/globe-land.json` contains land dots and country boundaries, generated by `scripts/generate-globe.mjs`.

## Gemini and Vercel

Keep your existing **GEMINI_API_KEY** in Vercel, enabled for the deployment environment you use. `Gemini_api_Key` and `GOOGLE_GENERATIVE_AI_API_KEY` are accepted as aliases. When only `GEMINI_API_KEY` is set, the server copies it onto `GOOGLE_GENERATIVE_AI_API_KEY` for SDKs that read that name. None is exposed to the browser. `GET /api/providers` reports `{ configured: true }` for each provider that has a key and does not return the secret. Model IDs are fixed in `lib/starcloud/catalog.ts`; arbitrary client-supplied models are rejected. The Gemini adapter prefers `gemini-3.8-flash`. If Google returns 404 for that id, the server tries the replacement named in the error and then other flash models (`gemini-3.6-flash`, `gemini-2.5-flash`, and the rest of the server allowlist). A 404 is not billed. Output caps are 512 tokens for ground and 360 for orbit. It reads provider token counts (including additional billed tokens in the total), excludes thought parts, and labels missing usage as estimated.

For public production chat, add **UPSTASH_REDIS_REST_URL** and **UPSTASH_REDIS_REST_TOKEN** from one shared Upstash Redis database. Redeploy after changing environment variables. Without Redis, the server still calls a configured model and applies an in-memory limit on that instance. If Redis is configured and unreachable, live requests fail closed.

Optional provider keys: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `XAI_API_KEY`. With `GEMINI_API_KEY` set, every listed model can answer. When a provider key is present, that provider is called directly. Without that key, the turn is still two calls on the Gemini key. The app makes **two** parallel calls per submission, one for each displayed reply. Cancellation propagates to the server where supported, but already-started work can still be billed.

`CHAT_DAILY_LIMIT` defaults to 200 paid requests per UTC day across every provider and every user. `APP_ORIGIN` optionally pins the canonical browser origin; otherwise the request URL origin is used, allowing Vercel preview URLs. Provider account budgets and Vercel Firewall are useful additional operational controls.

## What the numbers mean

**Measured:** token usage reported by the provider, when present. Call duration is kept with the reply and is not shown as a ground-versus-orbit route time. Both calls are ordinary provider API requests. This is not time to first token, the user's full end-to-end latency, or a live datacenter telemetry feed.

**Modeled:** network round trip on each path, plus each reply's token usage and adjustable IT energy (default 1.11 J/token, an illustrative parameter). Facility overhead uses PUE 1.04 for orbit (assumed), 1.09 for Google (2025 fleet average), or 1.10 for other ground providers (assumed). Ground cooling water uses an assumed 1.1 L/kWh midpoint; orbital evaporative cooling water is zero under a closed-loop radiator assumption. Electricity cost excludes hardware, networking, launch, capital expenditure and provider margin. The ground marker is the nearest public reference, not a server the provider identified.

The nearest site is selected from a **curated, non-exhaustive public reference catalog**, with approximate city/region coordinates. Google datacenters, AWS Bedrock regions, Azure AI regions and xAI endpoint regions are not equivalent kinds of physical sites. The user's pin does **not** control where direct provider APIs actually run the request. The app does not claim to locate private facilities or show real network traces.

Ground propagation is the surface path to that public site. The whitepaper says vacuum is 35% faster than typical glass fiber, so the path uses c/1.35. There is no invented city graph, cable allowance, or fixed overhead. The orbital request leaves the same user at the same moment. Starcloud-2’s diagram sends an end user over RF to a third-party backhaul, then over one optical link to Starcloud-2. The backhaul orbit is not published, so the RF satellite is the other drawn craft in the 600–850 km shell with the highest elevation. The optical leg is the straight vacuum distance when it clears Earth, otherwise the shorter arc on that shell. Both legs travel at c. The reply returns the same way.

The highlighted craft is Starcloud-2, the first commercial GPU smallsat, planned for sun-synchronous orbit in 2027. Starcloud-1 flew in November 2025 as an H100 demonstration; the results photo is that spacecraft. Starcloud-3 is the later, larger design associated with the February 2026 filing for up to 88,000 satellites. Starcloud-4 is the far-future multi-gigawatt concept, the same idea as the whitepaper’s 5 GW array, not this route. The scene draws about 8,800 craft in one dawn-dusk shell. They fill a volume along the ring, across 600–850 km, and a cross-track thickness, with a gap between neighbors. The drawing pulls that volume inward and outward; it is a spacing picture, not the 88,000 filing. Inclination is the sun-synchronous value at 725 km. The ring points its orbit normal at a fixed sun over 20°E, which is the paper’s dawn-dusk picture. That alignment is not a propagated ephemeris. The drawing lifts the band farther from the globe and stretches it radially; propagation uses physical kilometres. The dots are not the 88,000 filing and not an operating constellation. Starcloud-2’s hardware stands in for the paper’s compute containers, solar arrays, radiators, and RF/optical terminals. Positions freeze at submission. The camera begins with both paths in view, then follows the RF uplink, the optical link, and the return. If ground is the last route returning, the camera hands off to it. Playback multiplies physical light-time by one constant, so a longer path takes proportionally longer. Playback seconds are not literal latency; both returns wait for the real provider replies before animating. Weather, traffic, handovers and capacity are not simulated.

The white paper’s in-facility spine connects containers on one data center, within a few hundred meters. The optical leg in this scene is the link from the backhaul satellite to Starcloud-2, not that spine. A short ground path can be faster than the orbital light-time; the app does not force an orbital speed advantage.

## Verification and security

`npm test` runs deterministic geography, scenario, Gemini contract, other adapter and abuse-control tests with mocked provider responses. It makes no paid calls. See [SECURITY.md](SECURITY.md) for the review, deployment requirements and residual risks. Real provider credentials and production deployment must be verified separately; mocks cannot prove a specific key's permissions, quota or billing status.

The illustrated explanation uses figures extracted from Starcloud’s 2024 whitepaper. Image provenance is recorded in `public/research/CREDITS.md`; provider marks and their MIT license are in `public/providers/`.
